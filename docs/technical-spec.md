# 技术标准

## 开发环境和结构

- 用 Swift 开发原生 macOS 应用。建议最低支持 macOS 14，先在当前 Mac 上验收，最低版本在发布前核实。
- 用 SwiftUI 做列表和设置，用菜单栏图标承载历史面板，用 AppKit 的 `NSPasteboard` 读写系统剪贴板。全局快捷键先验证系统注册能力，注册失败时保留菜单栏入口，并在设置里提示。
- 首个菜单栏试用版使用现有的 Xcode 命令行工具构建。Swift 源码位于 `Sources/ClipboardHistory/`，应用配置位于 `Resources/Info.plist`。
- 在项目根目录运行 `/bin/sh scripts/build-app.sh`，生成当前 Mac 架构的 `build/剪贴板历史.app`。在 Finder 双击应用即可显示历史窗口，关闭窗口后仍可从屏幕右上角的剪贴板图标打开历史。按 `Esc` 收起当前面板，点面板内的「退出」结束运行。签名仅供本机开发试用。
- 从历史界面左下角进入「设置」，点按「在屏幕顶部显示剪贴板图标」，可重新启用已隐藏的图标。图标没有可用显示空间时，系统快捷键 `⌃⇧V` 可以打开独立历史窗口。快捷键注册冲突时保留 Finder 和菜单栏入口，并在窗口内提示。
- 分开实现剪贴板读写、历史存储、到期规则和界面。清理逻辑可使用指定时刻进行验证，避免为测试等待几天或修改系统时间。

## 剪贴板读写

- 用 `NSPasteboard.general.changeCount` 检测变化，只在有变化时尝试读取内容。读取前后确认变化编号一致，避免将新旧内容混作同一次复制。
- 尊重 macOS 的剪贴板访问设置。系统拒绝访问时，在界面提供可理解的提示和处理入口，避免反复触发提示。开发时验证允许、拒绝和重新允许后的行为。
- 保存完整纯文本或可重新粘贴的图片数据。界面文字截断和图片缩略图只用于显示。忽略空白或无法识别的数据。
- 已实现 PNG、TIFF、JPEG、GIF、HEIC 和 WebP 图片数据的识别。保留原始图片格式和数据，生成独立缩略图。忽略文件路径以及来源应用明确标为私密或临时的剪贴板项目。
- 成功把历史内容写回系统剪贴板后，跳过这次应用自身产生的变更。用户独立复制相同内容仍按一次复制处理。
- 剪贴板只能提供当前可读内容。已被下一次复制覆盖的数据，以及应用退出期间的数据，可能无法纳入历史。

## 存储与清理

- 首选应用专用目录下的本地 SQLite。记录包含稳定标识、类型、完整内容、复制时间和置顶状态。首版让图片数据与记录一起保存和删除，保证单次操作中的一致性。设置独立保存。
- 存储写入串行化，时间以统一时间戳记录，展示时转换为 Mac 本地时间。使用按时间降序与稳定标识排序，确保同一时间的卡片展示顺序稳定。
- 始终在清理条件里限制为未置顶。启动、定期运行和修改保留期限时用同一规则执行清理。用同一数据操作处理置顶变更和清理，避免先筛出记录后误删刚置顶的内容。
- 读取或写入失败时保留现有历史并提供错误提示。图片在需要时再解码，列表滚动时按需显示缩略图。
- 历史数据库保存在应用数据目录。项目代码、开发日志和一般错误日志只记录操作和错误状态。
- 运行时统一应用 1／3／5 天保留规则，默认 3 天。保留时间和删除前确认以本机偏好设置保存，调整时立即按新期限清理。数据库升级时保留现有记录和复制时间，旧记录默认未置顶。置顶、取消置顶和删除只更新指定记录。
